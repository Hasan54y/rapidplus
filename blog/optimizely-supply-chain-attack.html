Optimizely Supply-Chain Attack: Malware Hit Visitors of BBC, CNN, Zoom and 170+ Sites

One vendor script, 178 organisations, about 17 hours. What the malicious code did on the BBC, CNN, Zoom and others, and what to do if you visited.

Rapid+ Team · 23 Nov 2026 · 7 min read

On this page

The short versionWhat Optimizely is and why it mattersHow the attack workedWhat the malicious code didWho was affectedWhat you should doThe lesson about third-party scriptsFAQSources
Written on 23 November 2026. This story is still developing. The most detailed account is by Report URI, whose researcher Scott Helme found the attack, and we also drew on Krebs on Security and BleepingComputer. We did not read Optimizely's own incident report. Where sources disagree or nobody knows, we say so.

On 16 November 2026, malicious code was delivered to visitors of at least 178 well-known organisations through a single marketing tool, Optimizely. The affected sites include the BBC, CNN, Zoom, Equifax and the hardware wallet maker Ledger. For about 17 hours, pages that loaded Optimizely's script could swap cryptocurrency addresses, skim card numbers and try to attack older iPhones. The attack is over, but it shows how one trusted script can reach a very large audience at once.

This article explains what Optimizely is, what the code did, who might have been affected, and what you can do today, whether you only browse the web or run a website.

The short version

  • Attackers added malicious JavaScript to customer projects inside Optimizely Web, a tool that websites use for A/B testing and personalisation.
  • Report URI found 188 infected snippets belonging to 178 organisations among the 1,611 it could check. It says the real number is likely higher.
  • The code swapped crypto wallet addresses, tried to capture card details typed into a site's own forms, and sent cookies and screenshots to the attacker.
  • On iPhones and iPads running iOS 18.6 or earlier, it tried to load exploit kits named Coruna and DarkSword.
  • Report URI estimates about $7,000 to $7,500 in cryptocurrency reached the attacker's wallets. The number of stolen cards and cookies is unknown.
  • Optimizely says it has removed the injected code and fixed the vulnerability. How the attacker got in is not fully explained.

What Optimizely is and why it matters

Many large websites use Optimizely Web to test two versions of a page and see which works better. To do that, each customer loads a small script from Optimizely's servers on every page. That script can include a field called Project JavaScript, where the customer can add its own custom code. The script runs as soon as the page loads, before any cookie banner has been answered, as researcher Zach Edwards told Krebs.

That arrangement is the weak point. A site that trusts one vendor's script has handed that vendor the ability to run code on every visitor's browser. If an attacker can write into the vendor's system, they can reach every site at once, with no need to break into any of them.

How the attack worked

According to Report URI, the attacker wrote malicious code into the Project JavaScript field of customer projects. The rest of each script was unchanged, and it was still served from Optimizely's own domain with Optimizely's own certificate. Report URI stresses this was not a poisoned cache: Optimizely's network served exactly what it was given.

The injected code loaded a second script from a domain registered that morning. Report URI describes three loader variants, including one that carried a full copy of the payload so that blocking the domain would not stop it.

The attacker's two domains were put on hold by their registrar on 17 November, which stopped the code from loading even where it remained.

What the malicious code did

  1. Swapped crypto addresses. It replaced Bitcoin, Ethereum, Tron, Solana and other wallet addresses on the page, in the clipboard and in outgoing requests with the attacker's own. Copy an address from an affected site and you might have pasted the attacker's.
  2. Skimmed card details. From 13:43 UTC it watched forms for card numbers, expiry dates and security codes, and sent them to the attacker. Cards typed into hosted payment frames such as Stripe or Adyen were out of reach. Cards typed into a site's own fields were not.
  3. Sent cookies and screenshots. It collected the page address, cookies that are not marked HttpOnly, and a screenshot. Report URI says to treat any session tokens kept in such cookies as exposed.
  4. Tried to exploit iPhones. On iPhones and iPads it loaded exploit kits in a hidden frame: Coruna for iOS 13 to 17 and DarkSword for iOS 18. A third chain for iOS 26 only fingerprinted the device. Pages on iOS 18.6 or earlier reloaded every 60 seconds to retry.

Report URI cannot say how many cards, cookies or iPhones were affected. Krebs calls the iOS kits "zero-click" and says they chain together about six security holes, a description Report URI does not use. Whether any phone was actually compromised is not confirmed.

Who was affected

Report URI lists the BBC, CNN, Zoom, Salesforce, GitLab, IKEA, HSBC, Equifax, Air France-KLM, Ledger and Peacock among the 178 organisations. BleepingComputer, which says it confirmed the script on its own, adds Fox News, American Eagle, Smartsheet and UNICEF USA. Banking and finance made up the largest group in Report URI's table, with 32 organisations. At least 12 Dutch websites also warned visitors, according to NL Times.

Only people who loaded a page during the window could be affected, and the strongest signs of harm are for people who copied a crypto address, typed a card number or used an old iPhone. Most readers who visited these sites will have been unaffected.

What you should do

If you visited an affected site on 16 November

  • Update your iPhone or iPad to iOS 18.7.3 or later, or iOS 26.3 or later, which the kit's own code treats as patched.
  • If you sent cryptocurrency that day, check that the address you sent to matches the one you meant to use.
  • If you paid by card on one of these sites, watch your statement and ask your bank about anything you do not recognise. Our advice on paying safely explains why a card gives you the strongest protection.
  • Change passwords on sensitive accounts you used that day and prefer passkeys where offered.

If you run a website that used Optimizely

  • Open every project's Project JavaScript and each experiment's custom code, and look for the attacker's domain, atob( and any code you did not write.
  • Review who and what has write access to your Optimizely account, and rotate credentials.
  • Treat card data entered on your own forms that day as potentially exposed, and rotate secrets stored in cookies without HttpOnly.
  • Deploy a Content Security Policy that limits which domains scripts can load from and send data to. In Report URI's data, 24 of the 256 organisations it checked had a policy that blocked the payload, while 68 had none.

The lesson about third-party scripts

Every extra script on a page is a promise that its owner stays safe. Browsers cannot judge that promise for you, but you can reduce your exposure. A content blocker stops many third-party scripts from running at all, and Krebs notes that modern blockers can block most requests of this kind. Site owners can load fewer vendors, audit what they load and limit what scripts may do. Rapid+ Browser includes content blocking for this reason, though no blocker catches everything.

Frequently asked questions

Was the BBC or CNN itself hacked?

Not directly. The code came from Optimizely, a tool those sites use, and ran in visitors' browsers. Report URI says the vendor's network served exactly what it was given, so the tool's own systems were the point of attack.

Is the attack still going?

No. Report URI reports that all infected Optimizely files were clean by 23:11 UTC on 16 November and stayed clean. The attacker's domains were also put on hold on 17 November.

Could my iPhone have been hacked?

Only if it ran iOS 18.6 or earlier (or iOS 13 to 17) and loaded an affected page. Report URI says it cannot tell how many devices were infected. Updating to iOS 18.7.3, iOS 26.3 or later closes the holes the kit relied on.

How did the attacker get in?

That is not fully known. Report URI says it does not know how write access was obtained. Optimizely told BleepingComputer that the attacker used a vulnerability in its account signup flow and says it has fixed it.

How much money was stolen?

Report URI counted roughly $7,000 to $7,500 in cryptocurrency across the attacker's wallets. The number of stolen card records and cookies is not known.
